# 캘린더 / 기록 히스토리 백엔드 설계

## 범위

- 월간 캘린더 조회 API를 구현한다.
- 선택 날짜의 기록 타임라인 API를 구현한다.
- 데이터는 현재 구현된 `care_logs`만 사용한다.
- 프론트 코드는 수정하지 않는다.
- 사진 일기 데이터는 #19 연결 전까지 `hasDiary: false`, `diary: null`로 반환한다.

## 월간 캘린더 API

```http
GET /api/calendar?babyId={babyId}&year={year}&month={month}
```

기록이 존재하는 날짜만 `days`에 포함한다.

각 날짜는 다음 정보를 반환한다.

- 날짜
- 기록 존재 여부와 전체 개수
- 기록 유형 목록
- 수유·수면·소변·대변 유형별 개수
- `hasDiary: false`
- `thumbnailUrl: null`

## 일간 타임라인 API

```http
GET /api/calendar/daily?babyId={babyId}&date={date}
```

- 선택 날짜의 전체 기록을 발생 시각순으로 반환한다.
- 각 항목은 기록 ID, 유형, 시각, 사용자용 요약을 포함한다.
- 일간 요약은 수유 횟수, 총 수면 시간, 소변 횟수, 대변 횟수를 포함한다.
- 사진 일기는 현재 `diary: null`로 반환한다.

## 권한과 날짜

- 모든 API는 Bearer 인증이 필요하다.
- 로그인 사용자가 소유한 아기만 조회할 수 있다.
- 비소유자의 아기 ID는 `404 Baby not found`를 반환한다.
- 날짜 경계는 한국 시간(UTC+09:00)을 기준으로 계산하고 DB 조회는 UTC 범위로 변환한다.
- 연도는 `2000~2100`, 월은 `1~12`만 허용한다.

## 검증

- 기록이 없는 월과 날짜의 빈 응답
- 월말, 연말, 윤년 2월 범위
- 월간 날짜별 기록 유형과 개수 집계
- 일간 타임라인 정렬과 요약
- 한국 시간 자정 경계
- 미인증 `401`, 비소유자 `404`, 잘못된 입력 `422`
- Docker MySQL에서 기록 생성 후 월간·일간 재조회
