# 기록 프론트 API 연결 설계

## 범위

- 홈 빠른 기록에서 수유, 수면, 소변, 대변 생성 API를 호출한다.
- 기록 화면에서 선택 날짜의 저장 기록을 조회한다.
- 기존 일기와 캘린더 UI는 유지한다.
- 아기 ID는 `EXPO_PUBLIC_DEMO_BABY_ID`를 사용하며 기본값은 `1`이다.

## 구조

- `recordsApi`: Bearer 인증이 포함된 기록 생성과 목록 조회를 담당한다.
- 공통 타입: API 요청과 응답 형태를 화면 밖에 정의한다.
- 홈 화면: 기존 입력과 버튼 동작을 API 호출로 교체한다.
- 기록 화면: 선택 날짜가 바뀌거나 화면이 다시 활성화될 때 목록을 조회한다.

## 홈 빠른 기록

- 수유는 분유일 때 수유량, 모유일 때 수유 시간을 전송한다.
- 수면은 시작 시각을 보관하고 종료 시 시작·종료 시각을 전송한다.
- 기저귀 버튼은 소변과 대변 선택지를 표시하고 선택한 유형을 현재 시각으로 저장한다.
- 성공 시 최근 기록 문구를 갱신하고 입력창을 닫는다.
- 실패 시 오류를 표시하고 입력 상태를 유지해 재시도할 수 있게 한다.

## 기록 화면 조회

- 선택 날짜와 아기 ID로 `GET /api/records`를 호출한다.
- 최신 기록부터 시간, 유형, 주요 값을 표시한다.
- 로딩, 빈 상태, 오류 상태와 재시도 동작을 제공한다.
- 화면 재진입과 선택 날짜 변경 시 서버 데이터를 다시 조회한다.

## 인증 및 오류

- access token은 `useAuth`에서 가져온다.
- 보호 API에는 `Authorization: Bearer {token}`을 전달한다.
- 토큰이 없으면 요청하지 않고 로그인 필요 상태를 표시한다.
- HTTP 오류는 공통 API 모듈에서 사용자용 오류로 변환한다.

## 검증

- API 모듈 테스트에서 URL, 인증 헤더, 요청 본문과 응답 변환을 검증한다.
- TypeScript 타입 검사를 통과해야 한다.
- Docker 백엔드와 MySQL에서 생성 후 목록 재조회를 확인한다.
